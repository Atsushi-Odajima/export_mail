# Samurai Dealer Research（英国中古車販売店の調査・営業アプリ）

日本から英国への中古車販売の営業候補として、英国の中古車販売店を**発見・調査**し、分類・日本語概要・公開メールまたは問い合わせ方法・出典を確認したうえで、**営業メールの作成・承認・送信・予約配信・返信管理**までを行う日本語アプリです。

- **調査機能**は外部 AI・有料 API・クレジットカード登録なしで動きます（候補発見の Firecrawl だけは任意）。
- **営業メール機能**（版 1.2.0 から）：テンプレート／手動／AI（コピー貼り付け・API）で英文を作り、人が承認した版だけを、Gmail API・Microsoft Graph（Outlook）・SMTP/IMAP のいずれかで送ります。予約配信、返信の取り込みと分類、返信があったときの追客停止、配信停止の管理、送信結果不明時の照合を備えます。説明は「[4. 営業メール](#4-営業メール版-120-から)」。
- **送信モードの初期値は「停止」**です。公開メールが見つかっても、それは送信してよいという意味ではありません。送るかどうかは案件ごとに人が判断して記録します。
- 実装状況（どこまで試験したか、何が認証・設定待ちか）は [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md)、外部サービスの公式情報の確認記録は [docs/EXTERNAL_SERVICES.md](docs/EXTERNAL_SERVICES.md) にあります。
- 確認済みの初期データ（実在の英国販売店）を同梱しています。内容と確認方法は [docs/INITIAL_DATA_REPORT.md](docs/INITIAL_DATA_REPORT.md)、検証結果は [docs/VERIFICATION.md](docs/VERIFICATION.md) を参照してください。

主な使い方は **Windows（PC）版** です（以下の説明）。

## iPhone 版（補助）

外出先などで iPhone から一覧を見たり調査したりする場合は [mobile/README.md](mobile/README.md) を参照してください。Cloudflare の無料プラン（Workers ＋ D1）に置く Web アプリで、調査の規則・データの形・販売店ID は Windows 版と共通です（データは PC 版とは別に保存され、自動では同期しません）。

## 1. インストールと起動（Windows 版）

### インストール（おすすめ）

1. `SamuraiDealerResearch-Setup-1.2.0.exe` を入手します（GitHub の Actions → `windows-build` の最新の成功した実行 → Artifacts の `SamuraiDealerResearch-Setup`。成果物は 30 日で消えるため、必要なら Windows PC で `scripts\build_windows.bat` を実行して作り直せます）。
2. ダブルクリックしてインストールします。**管理者権限は不要**です（利用者ごとに `%LOCALAPPDATA%\Programs\SamuraiDealerResearch` に入ります）。
   - 署名のないアプリのため、初回に「Windows によって PC が保護されました」が出ることがあります。「詳細情報」→「実行」で進めます。
   - 「デスクトップ上にアイコンを作成する」を選ぶと、デスクトップにも起動用のアイコンができます。
3. スタートメニュー（またはデスクトップ）の **Samurai Dealer Research** で起動します。アプリ専用のウィンドウが開きます（画面の表示には Windows 標準の Microsoft Edge WebView2 を使います）。

### 使い方の要点

- **終了**：ウィンドウを閉じるか、画面右上の「アプリを終了」を押します。調査の実行中、または予約済みの送信があるときは確認が出ます（中断した調査は次回「再開」できます。**終了中は予約メールの送信と返信の確認も止まります**）。
- **もう一度起動したとき**：すでに開いていれば、新しく起動せずに既存のウィンドウを前面に出します。
- **販売店のサイトなど外部へのリンク**：アプリのウィンドウではなく、いつもの既定のブラウザーで開きます。
- **CSV・バックアップの保存**：「名前を付けて保存」の画面で保存先を選べます。
- 待ち受けはこの PC 内（127.0.0.1）だけです。ほかの PC からは見えません。
- Microsoft Edge WebView2 が入っていない PC では、従来どおり既定のブラウザーで画面を開きます（Windows 11 には標準で入っています。Windows 10 でも通常は Edge の更新で入っています）。

### 更新・アンインストール

- **更新**：新しい版のインストーラーをそのまま実行します。アプリの起動中は終了を案内されます。データは別の場所にあるため消えません。データベースの形が変わる版では、起動時に自動で更新し、その直前に自動でバックアップを作ります（「6. バックアップ・復元・更新」）。
- **アンインストール**：Windows の「設定」→「アプリ」→「インストールされているアプリ」→ Samurai Dealer Research →「アンインストール」。アプリ本体だけを削除し、**調べたデータは残します**（不要なら下の保存場所のフォルダーを手動で削除してください）。

### インストールせずに使う場合（ZIP 版）

Artifacts の `SamuraiDealerResearch-windows-zip` を任意の場所に展開し、`SamuraiDealerResearch.exe` を起動します（使い方は同じです）。

### コマンド用の実行ファイル

同じフォルダーの `SamuraiDealerResearch-cli.exe` は、メッセージを黒いウィンドウに表示するコマンド用です（共有モード・バックアップ・復元・利用者の作成など。下の各節のコマンド例はこちらを使います）。引数なしで起動すると、従来どおり既定のブラウザーで画面を開きます。

Python の導入は不要です。対象は Windows 10/11（64bit）です。

### データの保存場所

`%LOCALAPPDATA%\SamuraiDealerResearch`（例：`C:\Users\あなた\AppData\Local\SamuraiDealerResearch`）

| ファイル | 内容 |
|---|---|
| `dealers.sqlite3` | 正本のデータベース（販売店・連絡方法・根拠・履歴・候補・ジョブ・案件・文面・承認・予約・送受信の記録・配信停止・監査記録） |
| `attachments\` | 文面に付けた添付ファイル |
| `backups\` | バックアップ ZIP、更新前の自動バックアップ |
| `logs\app.log` | 動作記録（APIキー・パスワード・トークン・メール本文は書きません） |
| `instance.json` | この PC の稼働環境の識別（コピー・復元の検出用。DB とは別に置きます） |

**パスワード・OAuth の更新トークン・API キー**（メール接続・Claude API・Firecrawl）は **Windows の資格情報マネージャー**（OS の資格情報保管）に保存し、データベース・バックアップ・CSV・ログには入れません。資格情報保管が使えない環境だけ、データフォルダーの `secrets.json`（所有者のみ読み書き可）に保存します。どちらに保存しているかは「メール・AI設定」画面に表示します。

アプリ本体のフォルダーを新しい版に置き換えても、このデータは消えません。**各 PC に配布した場合、データは PC ごとに別々で、自動では同期しません。** 同じ一覧を複数人で使う場合は「7. 共有モード」を使ってください。

## 2. 画面の操作

| 画面 | できること |
|---|---|
| **ダッシュボード**（起動時の画面） | 送信モード、予約処理の稼働状態、メール接続の状態、販売店数・進行中の案件・下書き・承認待ち・予約済み・保留・7日間の送信・送信結果不明・新着返信などの件数。営業メールの画面は「[4. 営業メール](#4-営業メール版-120-から)」 |
| **販売店一覧** | 店名・地域・分類・概要・公開メール・問い合わせ方法・確認日・調査状態の一覧。店名／地域／分類／メールあり／フォームあり／要確認／調査状態で絞り込み。CSV 出力。選択した販売店の（再）調査 |
| **詳細** | 調査根拠（抜粋・出典を開く・観測日時）、連絡方法ごとの状態と出典、手動編集、メモ、人の確認、再調査、重複・支店の整理、取得ページの記録、変更履歴 |
| **候補発見** | 地域・分野・件数を指定して候補を集める。**自動検索**（OpenStreetMap・Firecrawl）と**手動補助**（検索ページをブラウザーで開くだけ）を分けて表示 |
| **候補一覧** | 発見した候補を確認し、販売店として登録・調査開始・除外 |
| **URL追加・CSV取込** | 公式サイトの URL を貼り付け、または CSV で取込み、そのまま調査開始 |
| **調査の進捗** | 進捗・停止・再開・失敗分の再実行・失敗理由 |
| **設定・バックアップ** | 取得の設定、Firecrawl APIキー、バックアップ・復元、初期データの読込 |

### 表示の意味（大事な点）

- **分類根拠**：「公式に専門店と明記」＝公式サイトに専門・販売の記載がある。「確認した在庫からの傾向」＝確認した在庫ページの範囲での傾向（全在庫は未確認で、専門店とは限らない）。「要手動確認」＝自動では判断できない。
- **公開メール確認済み**：販売店の公式サイトで公開表示を確認しただけです。**届くかどうか、営業メールを送ってよいかは確認していません。** 確認メールや SMTP 接続による宛先検査もしません。
- **公開メール未確認**：調べた範囲で見つからなかったという意味で、メールが存在しないとは限りません。
- **除外**：求人用・個人情報窓口・制作会社等のアドレスは販売店の窓口として採用しません（理由を表示）。別ドメインのアドレスは「要手動確認」です。
- **フォーム確認済み**／**問い合わせページあり・フォーム未確認**／**要手動確認**：検索欄・ログイン・ニュースレター登録は問い合わせフォームに数えません。外部サービスの埋め込み（HubSpot 等）で中身が見えない場合は「要手動確認」です。
- **人が確定**：人が入力した値。再調査しても上書きしません。空欄で保存すると自動取得値の表示に戻ります。

### 調査の流れ

1. 候補を集める（候補発見・URL 貼り付け・CSV）。URL の推測や架空企業の登録はしません。
2. 調査：トップ・会社紹介・問い合わせ・在庫ページなど（既定で 1 サイト最大 10 ページ）を取得し、店名・所在地（郵便番号）・中古車販売の記載・分類・メール・フォーム・電話を抽出します。
3. 人が詳細画面で根拠を見て、名称・公式サイト・分類・連絡方法を確認し「人が確認済みにする」を押します。

調査はバックグラウンドで進み、画面は操作できます。アプリを閉じても完了分は保存され、未完了分は「調査の進捗」から**再開**できます。

### 取得の制約（サイトに負荷をかけないため）

- robots.txt を確認し、不許可のページは取得しません。
- 同一サイトへの同時取得 1、取得間隔 2 秒以上、全体の同時調査 2、1 サイト最大 10 ページ（設定で変更可。間隔は 2 秒未満にできません）。
- 通信の制限時間 15 秒、1 ページ最大 2MB、再試行 1 回、取得キャッシュ 24 時間。
- アクセス制限・CAPTCHA・ボット確認ページ・HTTP 403 は**回避しません**。「取得失敗（理由）」として記録するので、ブラウザーで確認して手動で登録してください。
- http/https の公開 URL だけを扱います。localhost・内部 IP・クラウドの管理用アドレス・ローカルファイル等は、転送先や名前解決後のアドレスも含めて拒否します。
- 取得した HTML は実行せず、画面では文字として表示します。外部ページの文章をアプリへの命令として扱いません。

## 3. 追加調査（新しい販売店を探す）

### A. OpenStreetMap（無料・APIキー不要・自動）

候補発見 → 地域を選ぶ →「OpenStreetMap から候補を集める」。OpenStreetMap に `shop=car`（自動車販売店）として登録され、ウェブサイトが記載された店を集めます。

- 利用するサービス：Overpass API の公開インスタンス（OSM Wiki の一覧 https://wiki.openstreetmap.org/wiki/Overpass_API に掲載。英国・アイルランド向けの `overpass.atownsend.org.uk` を優先し、つながらない場合に `overpass-api.de`、`maps.mail.ru` の順で試します）。主インスタンスの利用方針は「1 日 1 万回未満・1GB 未満なら他の利用者の妨げにならない、定常利用はその 1/100 程度、並列実行しない」（2026-10-24 確認）。本アプリは 1 回の操作で 1 回だけ問い合わせます。混雑時は失敗することがあり、稼働保証はありません。
- データ：© OpenStreetMap contributors（ODbL 1.0）。登録内容は有志による入力で、網羅的ではありません。新車ディーラーも含まれるため、調査で中古車販売を確認します。
- この開発環境では `overpass.atownsend.org.uk` 経由で実際に候補を取得できることを確認しました（docs/VERIFICATION.md 参照）。`overpass-api.de` はこの環境の回線制限で接続できず未検証です。

### B. Firecrawl 検索（任意・APIキーが必要）

設定画面で APIキーを入れた場合だけ使えます（https://www.firecrawl.dev/ で登録）。

- 2026-10-24 に公式料金ページ（https://www.firecrawl.dev/pricing ）で確認した内容：Free プランは **毎月 1,000 クレジット・クレジットカード不要**、検索は **10 件あたり 2 クレジット**、同時 2 リクエスト。料金・条件は変わることがあるため、使う前に公式ページで確認してください。商用利用の制限は料金ページに記載がありませんでした（利用規約は各自で確認）。
- アプリ側の上限：月間使用上限（既定 200 クレジット）と 1 回あたりの最大件数（既定 20 件）。上限に達すると実行しません。残高不足（HTTP 402）でも止まり、**有料プランへ自動で切り替えません**。
- 使用量はデータベースに記録します。APIキーは OS の資格情報保管（Windows 資格情報マネージャー）に保存し、データベース・バックアップ・CSV・ログには入れません。
- APIキーを持っていないため、**この開発環境では実際の検索は未検証**です（応答の読み取りは試験で確認）。

### C. 手動補助（ブラウザーで開くだけ）

候補発見画面の Google・Bing・Google マップ・OpenStreetMap のリンクは、検索語を入れた検索ページを新しいタブで開くだけです。**アプリは検索結果を取得しません。** 見つけた販売店の公式サイト URL を「URL追加」に貼り付けてください。車両掲載サイト（AutoTrader 等）やアイルランドのサイトは登録できません。

### D. CSV 取込

見出しに `URL`（または `公式サイト` / `website`）列が必要です。任意で `店名` `地域` `メモ`。UTF-8 または Shift_JIS、2MB・2000 行まで。

## 4. 営業メール（版 1.2.0 から）

### 大事な約束（アプリの動き）

- **送信モードの初期値は「停止」**です。「停止」の間は、予約も「今すぐ送信」も一切送りません。
- **承認した版だけを送ります。** 承認後に宛先・件名・本文・添付・送信元を 1 文字でも変えると承認は自動で取り消され、予約は「承認待ち」に戻ります。
- **公開メールは送信許可ではありません。** 「実送信」モードでは、案件ごとに人が「送信可」と**その根拠**（例：問い合わせ窓口として公開、商談の同意あり）を記録した案件にしか送りません。
- 送信できない理由（未承認・差し込み漏れ・配信停止・未対応の返信・受信確認が古い・1 日の上限 など）は、送信の直前にもう一度確認し、日本語で表示します。送信しなかった予約は「保留」になり、勝手に再送しません。
- 「受付済み」は**メールサービスが受け付けた**という意味で、相手に届いた・読まれたことの確認ではありません。
- 通信が途中で切れるなどして送ったかどうか分からない場合は「**結果不明**」とし、自動では再送しません（二重送信を防ぐため）。「照合・送信担当」画面で送信済みフォルダーと照合するか、人が判断します。

### 最初の設定（順番どおりに）

1. **自社情報**（メニュー「文面」→「自社情報」）：会社名・送信者名・肩書・会社紹介・扱う車両・サービス・署名（英語）。テンプレートの差し込みに使います。
2. **メール接続**（メニュー「メール・AI設定」→「追加：」のボタン）：まず **テスト用接続先** を追加して動きを確かめるのがおすすめです（外部へ一切送らず、アプリ内の「テスト用受信箱」に記録します）。実際のアカウントは下の「メール接続の準備」を参照してください。
3. **送信モード**（「メール・AI設定」）：
   - **停止**（初期値）：送らない。
   - **テスト**：テスト用接続先はアプリ内に記録するだけ。**実際のアカウントで送る場合は、件名に `[TEST]` を付け、宛先を「検証用の宛先」（あなたが指定する自分のアドレス）に置き換えて送ります。** CC・BCC は付けず、案件の状態も進めません。販売店には届きません。
   - **実送信**：確認欄にチェックして切り替えます（管理者のみ）。案件の「送信可」と根拠の記録が必要です。
4. 必要に応じて **テンプレート**（「文面」→「テンプレート」）を自社向けに直します。分類（スポーツカー・4x4/SUV・クラシック・一般）ごとの初回、2 回目・3 回目の追客、掘り起こし、返信の雛形が入っています。差し込み項目は `{{dealer_name}}` `{{town}}` などで、空欄のままの項目があると承認できません。

### 1 通送るまでの流れ

1. 販売店の詳細画面（または「案件」画面）で **案件** を作ります（担当者・段階・次の対応・メモを管理）。
2. 案件画面で **下書き** を作ります。作り方は 3 通り：
   - **テンプレート**（AI 不要）：販売店の分類・地域・自社情報を差し込んで英文を作ります。
   - **手動**：自分で書くか、画面に表示される「AI へ渡す指示文」をコピーして、手元の ChatGPT・Claude などに貼り、返ってきた英文を「AI の結果を貼り付け」欄に貼ります（件名・本文・日本語要約に分けて取り込みます）。**API キー不要・無料**で使えます。
   - **AI で作る**（任意）：「メール・AI設定」で Claude API キーを入れて有効にした場合だけ使えます（下記「AI の設定」）。
3. 下書き画面で英文・日本語要約・作成根拠・同じ販売店に以前送った文面との類似（似すぎると警告）を確認し、必要なら編集して **「この版を承認」**。
4. **今すぐ送信**（確認欄にチェックが必要）または **予約**（日本時間／英国時間で指定）。
   - 英国時間で指定した場合、夏時間の切り替えで存在しない時刻はエラーにし、2 回ある時刻はどちらか選んでもらいます。保存は UTC、画面は日本時間または英国時間で表示します（上部で切替）。

### 予約配信（初回＋追客）

- 案件画面の「初回・2回目・3回目・掘り起こしをまとめて予約」で、まとめて予約できます。各回の文面を承認すると「予約済み」になります（承認するまでは「承認待ち」で、送りません）。
- **返信があれば追客を止める**（初期値オン）：返信を取り込むと、その案件の 2 回目・3 回目の予約は自動で「取消」になり、同じ販売店のほかの予約は「保留」になります。
- 追客を送る直前には受信を確認し、受信の確認が古い（初期値 30 分より前）場合は送らずに保留にします。
- 予約は **このアプリが起動している間だけ** 処理します。PC の停止・スリープ中は送られず、予定時刻を 10 分（設定で変更可）より過ぎた予約は自動では送らずに「保留（遅延）」にします。再開・日時変更・取消は「送信・予約」画面で行います。
  - **予約どおりに送るための準備**：送信する時間帯はアプリを起動したままにし、PC がスリープしないようにします（Windows の「設定」→「システム」→「電源」→「画面とスリープ」で、電源接続時のスリープを「なし」にする。ノート PC はふたを閉じたときの動作も「何もしない」に）。予約処理の状態（稼働中・最後の実行時刻）はダッシュボードに表示します。
  - 英国の営業時間（日本時間の夕方〜深夜）に送る場合は、その時間に PC を起動しておく必要があります。常時稼働が難しい場合は、日本時間の日中に送る予約にしてください。
- 「送信・予約」画面：一時停止・再開・日時変更・複製・取消、「全送信を停止」（送信モードを「停止」にします。予約は残りますが送られません）、「今すぐ受信確認・予約処理」。

### 返信の管理

- 受信は 5 分ごと（設定で変更可）と「受信を確認」ボタンで取り込みます。営業に関係するメール（こちらが送ったメールへの返信、または送信先と同じアドレス・ドメインからのメール）だけを保存し、**関係のないメールは保存しません。**
- 返信の結び付けは「返信の参照（In-Reply-To／References）→ スレッド → 同じアドレス → 同じドメイン（要確認として表示。Gmail などのフリーメールは対象外）」の順です。違っていれば受信画面で付け替えられます。
- 自動で分類します：**返信**／**自動応答**（不在通知など）／**不達通知**（宛先不明）／**配信停止の依頼**／**拒否の疑い**（not interested など）。分類は受信画面で直せます。
  - 配信停止の依頼：そのアドレスを「送信停止（確定）」、会社全体を「送信停止（確認待ち）」にします。
  - 不達通知：届かなかった宛先を「無効な宛先」として送信停止にします（宛先が特定できなければ、その販売店の予約を保留）。
  - 返信・配信停止の依頼・拒否の疑いを受けると、その販売店のほかの予約を保留にし、受信を「対応済み」にするまで送りません。
- 受信画面で「対応済み」にする、日本語要約（AI 設定時）、返信の下書きを作る、ができます。**返信も自動では送りません**（下書き → 承認 → 送信）。

### 送信停止（配信停止・連絡拒否・無効な宛先）

- 「送信停止」画面で、アドレス単位・ドメイン単位・販売店単位の停止を登録できます。「確定」と「確認待ち」の**どちらも送信を止めます**。解除は管理者だけができ、記録が残ります。
- 本文末尾の配信停止の案内：公開用の HTTPS アドレス（「メール・AI設定」の「配信停止リンク用の公開アドレス」）を設定した場合はリンクを付けます（共有モードで外部公開している場合のみ意味があります）。未設定なら「unsubscribe と返信してください」という案内を付け、その返信を自動で配信停止の依頼として扱います。

### 送信結果の照合（結果不明・PC の移動・復元）

- 「照合・送信担当」画面（ダッシュボード、または「メール・AI設定」から）に、結果不明の送信と、照合が必要な理由を表示します。「送信済みフォルダーと照合」（Gmail API・Graph は送信済みを検索。SMTP は Gmail の場合のみ）か、人が「送信済みと判断」「未送信と判断」を選びます。
- データベースを別の PC にコピーした、古いバックアップを復元した、などを検出すると、**照合が終わるまで送信を止めます**。確認後に「この環境を送信担当にする（照合後）」を押すと再開します（同じデータで 2 台が同時に送らないため）。

### メール接続の準備（実際のアカウント）

> 開発中の試験はテスト用接続先だけで行い、実際のアカウントでの送受信は**未検証**です（[IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md)）。最初は送信モード「テスト」と検証用の宛先（自分のアドレス）で確認してください。

**A. Gmail（Gmail API・おすすめ）**
1. Google Cloud コンソール（https://console.cloud.google.com/ ）でプロジェクトを作り、「Gmail API」を有効にします（無料）。
2. 「OAuth 同意画面」を作成（種類：外部）。自分のアドレスを「テストユーザー」に追加します。使うスコープは `gmail.send`（送信。Google の区分では「機密」）と `gmail.readonly`（受信の確認。区分は「制限付き」）です。
3. 「認証情報」→「OAuth クライアント ID」→ 種類「**デスクトップ アプリ**」。表示されたクライアント ID とクライアントシークレットを、アプリの Gmail 接続画面に入力して保存します（リダイレクト URI の登録は不要で、アプリは `http://127.0.0.1:ポート/oauth/callback` を使います）。
4. 「接続する（ブラウザーで認証）」→ Google の画面で許可します。「確認されていないアプリ」の警告が出たら、自分で作ったアプリであることを確かめて進みます。
5. 注意：同意画面が「テスト」のままだと、**7 日ごとに再認証が必要**です（Google の仕様）。「本番」に切り替えると個人利用（100 人未満）では審査なしで使えますが、警告画面は出ます。

**B. Outlook.com／Microsoft 365（Microsoft Graph）**
1. Microsoft Entra 管理センター（https://entra.microsoft.com/ ）→「アプリの登録」→「新規登録」。アカウントの種類は使うアカウントに合わせます（個人の Outlook.com を含めるなら「個人の Microsoft アカウント」を含む種類）。
2. 「認証」→「プラットフォームを追加」→「**モバイル アプリケーションとデスクトップ アプリケーション**」→ リダイレクト URI に `http://localhost` を追加します（ポート番号は照合に使われません）。「パブリック クライアント フローを許可」は不要です。
3. 「API のアクセス許可」に Microsoft Graph の委任されたアクセス許可 `Mail.Send` `Mail.ReadWrite` `User.Read` `offline_access` を追加します。
4. 「アプリケーション（クライアント）ID」をアプリの Outlook 接続画面に入力し、アカウントの種類（個人／組織／両方）を選んで保存 →「接続する」。クライアントシークレットは使いません。
5. 送信は「下書きを作成 → 送信」の 2 段階で行い、送信済みの照合に使う ID を記録します。

**C. SMTP／IMAP（パスワード方式）**
- Gmail の場合：Google アカウントで 2 段階認証を有効にし、「アプリ パスワード」を作って、接続画面の「よく使う設定：Gmail」を選び入力します（`smtp.gmail.com:587` STARTTLS、`imap.gmail.com:993`）。仕事用アカウントなどでは作れない場合があります。
- **Outlook.com は 2024 年 9 月 16 日にパスワード方式（基本認証）が廃止**されたため、この方式では使えません。B の Graph を使ってください。
- その他のメールサービス：提供元の SMTP・IMAP の設定値を入力します。IMAP を設定しないと受信の確認ができず、追客は「受信確認が古い」として保留になります。

**共通**：アプリ側の 1 日の送信上限（初期値 30 通）を接続ごとに設定できます。サービス側の上限は別にあります（[docs/EXTERNAL_SERVICES.md](docs/EXTERNAL_SERVICES.md)）。接続画面の「切断」で保存した認証情報を削除し、その接続の予約を保留にします。

### AI の設定（任意・有料）

- 「メール・AI設定」で Anthropic の **Claude API キー**（https://console.anthropic.com/ で発行）を入れ、「AI による文面作成を使う」をオンにした場合だけ動きます。**Claude API に無料枠はありません**（新規利用者には少額の試用クレジットがある、と公式料金ページに記載）。キーを入れなくても、テンプレートと「手動（コピー貼り付け）」で全機能を使えます。
- モデル（初期値は高性能な最新モデル。安価なモデルも選べます）、考える深さ、**月間の呼び出し回数・トークン数の上限**（初期値 200 回・200 万トークン）を設定できます。上限に達すると呼び出しません。使用量は画面に表示します。
- 安全上の理由で応答が断られた場合に別のモデルで自動的にやり直す設定（初期値オン）があります。
- AI に渡すのは、販売店の調査結果（公開情報の抜粋）・自社情報・これまでのやり取りの要約です。**販売店サイトの文章や受信メールの中の指示には従わないよう**指示しています。AI の作った英文も、必ず人が確認して承認してから送ります。

### 送信と共有モードの役割

- 共有モードでは利用者に **管理者**（最初に作った利用者）と **担当者** の役割があります。担当者は案件・下書き・承認・予約・受信対応ができ、管理者だけが送信モードの切り替え、メール接続・AI の設定、配信停止の解除、利用者管理、送信担当の引き継ぎを行えます。
- 送信モード・承認・送信・送信停止・設定変更などは「操作履歴」画面（「メール・AI設定」から）に残ります。

## 6. バックアップ・復元・更新

### バックアップ

設定・バックアップ画面の「今すぐバックアップ」で `backups\sdr-backup-日時-manual.zip` を作ります（画面からダウンロードも可）。中身はデータベース全体（販売店 ID・人の確定値・根拠・変更履歴・候補・案件・文面と承認の履歴・予約・送受信の記録・送信停止・操作履歴）、添付ファイル、説明ファイルです。取得キャッシュ・ログイン中のセッション・**パスワード・トークン・API キーは含めません**（復元先の PC ではメール接続の再認証と API キーの再入力が必要です）。

コマンドでも作れます：`SamuraiDealerResearch-cli.exe backup`

### 復元

画面の「復元」で ZIP を選び、確認欄にチェックして実行します。**復元の直前に現在のデータを自動でバックアップ**します（`before-restore` の ZIP）。アプリを終了した状態でコマンドから復元することもできます：`SamuraiDealerResearch-cli.exe restore バックアップ.zip`

復元すると、二重送信を防ぐため**送信モードを「停止」にし、送信結果の照合が終わるまで送信しません**。「照合・送信担当」画面で、結果不明の送信や復元後に送ったかもしれない予約を確認してから「この環境を送信担当にする（照合後）」を押し、送信モードを戻してください。データベースを別の PC にコピーした場合も同じです。

### アプリの更新（データを保持したまま）

1. 画面でバックアップを作る（念のため）。
2. アプリを終了し、新しい版のインストーラーを実行する（ZIP 版の場合はアプリのフォルダーを新しい版に置き換える。データフォルダーには触れない）。
3. 新しい版を起動すると、データベースの版（`schema_meta.schema_version`）を確認し、必要な更新（列・テーブルの追加）を自動で行います。**更新の直前に `backups\pre-migration-v版-日時.sqlite3` を自動作成**します。

### 更新に失敗したとき

- 更新処理は 1 段階ずつトランザクションで行い、失敗したら更新前の状態に戻して起動を止めます（データは更新前のまま）。
- 元に戻すには：旧版のアプリに戻すか、アプリを終了した状態で `backups\pre-migration-...sqlite3` を `dealers.sqlite3` という名前でデータフォルダーに上書きコピーします（`dealers.sqlite3-wal` `-shm` があれば削除）。
- 新しい版で作ったデータベースを古い版で開こうとすると、壊さないよう起動を止めます。

## 7. 共有モード（自分の PC をサーバーにして友人と使う）

データはサーバー役の PC にだけ保存し、利用者はブラウザーから同じ一覧を使います。SQLite ファイルをネットワーク共有して各 PC から直接開く使い方はしないでください。小規模（2 人程度）を想定しています。

### 準備（サーバー PC）

```bat
SamuraiDealerResearch-cli.exe create-user alice
SamuraiDealerResearch-cli.exe create-user bob --role member
```

**最初に作った利用者が管理者**になります（`--role admin` / `--role member` で指定も可）。管理者は画面の「メール・AI設定」→「利用者」でも利用者の追加・役割変更・無効化ができます。管理者と担当者でできることは「4. 営業メール」の「送信と共有モードの役割」を参照してください。

パスワード（10 文字以上）は対話で入力します。既定の共通パスワードはありません。パスワードは scrypt でハッシュ化して保存し、ログイン後は HttpOnly・Secure・SameSite のセッション Cookie（12 時間）で管理します。更新操作はすべて CSRF トークンで保護し、5 回続けて失敗すると 15 分間ログインを受け付けません。

```bat
SamuraiDealerResearch-cli.exe shared --allowed-host あなたの公開ホスト名
```

既定では `127.0.0.1:8780` だけで待ち受けます（ログイン必須。未ログインでは一覧・CSV・調査実行の API に到達できません）。127.0.0.1 以外で待ち受ける場合は HTTPS 証明書（`--certfile` `--keyfile`）が必要で、指定がなければ起動しません。**ルーターのポート開放は手順にしていません。**

### 接続方法（HTTPS の経路）

| 方法 | 位置づけ | 無料か | 注意 |
|---|---|---|---|
| Cloudflare Quick Tunnel（`cloudflared tunnel --url http://127.0.0.1:8780`） | **一時的な試用用** | アカウント不要 | 公式に「試験・開発用」、稼働保証なし、起動のたびに URL が変わる（2026-10-24 確認：https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/ ）。表示された `xxxx.trycloudflare.com` を `--allowed-host` に指定 |
| Cloudflare Tunnel（名前付き） | 継続運用向け | Cloudflare のアカウントは無料で作れるが、**インターネットに公開するには Cloudflare に登録した自分のドメインが必要**（ドメイン代は有料）（公式手順の前提条件、2026-10-24 確認） | Cloudflare Access（Zero Trust）で利用者のメール認証を前段に置くとより安全。Zero Trust の無料枠の人数上限などは導入時に公式ページで確認 |
| Tailscale | 継続運用の代替 | Personal プランは無料だが、公式に**非商用のみ**（2026-10-24 確認：https://tailscale.com/pricing ）。業務利用は有料プラン | 業務で「完全無料」とは扱えません |

外部公開・サービス契約はこのアプリからは行いません。利用者自身が判断して設定してください。

### 注意

- サーバー PC が停止・スリープ・回線切断中は利用できません。
- 共有モードでは画面から終了できません。サーバー PC のウィンドウで `Ctrl+C` を押します。
- 共有モードで調査を実行すると、取得はサーバー PC の回線から行われます。
- メールの送信・予約処理・受信の確認もサーバー PC で行います。メール接続（OAuth の認証）は**サーバー PC のブラウザーで**行ってください（認証の戻り先が `127.0.0.1`／`localhost` のため）。
- 配信停止リンク（`/u/…`）はログインなしで開ける唯一のページです。公開アドレスを設定した場合だけ本文に入ります。

## 8. 開発者向け

```sh
uv venv -p 3.12 .venv            # または python -m venv .venv
. .venv/bin/activate             # Windows: .venv\Scripts\activate
pip install -r requirements.txt -r requirements-dev.txt
python -m pytest -q tests        # 試験（架空データのみ使用）
python run_app.py local          # 開発用起動（--data-dir で保存先を変更可）
```
