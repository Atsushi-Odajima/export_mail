# Samurai Dealer Research — iPhone 版

英国の中古車販売店を調べ、分類・日本語概要・公開メールまたは問い合わせ方法・出典を iPhone で確認するアプリです。
PC は不要です。Cloudflare の無料プラン（Workers ＋ D1）で動き、iPhone の Safari からホーム画面に追加して使います。

- 外部 AI・有料 API・クレジットカード登録は不要です（Firecrawl は任意。自分のキーを登録したときだけ使います）。
- メールの作成・送信、問い合わせフォームへの入力・送信はしません。将来の追加方法は [../FUTURE_EMAIL_PLAN.md](../FUTURE_EMAIL_PLAN.md) を参照してください。
- 確認済みの英国販売店 30 社の初期データを同梱しています（初回設定のあと画面から読み込みます）。

## 1. 導入（iPhone だけでできます。所要 10〜15 分）

Cloudflare のアカウント作成と公開は、利用者ご本人の操作です（このアプリから代わりに契約・公開はしません）。

1. **Cloudflare の無料アカウントを作る**
   Safari で https://dash.cloudflare.com/sign-up を開き、メールアドレスとパスワードで登録します（無料プランはカード登録不要）。
2. **GitHub と接続してこのリポジトリを読み込む**
   Cloudflare の画面で「Workers & Pages」→「作成（Create）」→「リポジトリをインポート（Import a repository）」を選び、GitHub を接続して `export_mail` リポジトリを選びます。
   - **ルートディレクトリ（Root directory / Path）に `mobile` を指定**します。
   - ビルドコマンドは空欄のまま、デプロイコマンドは `npx wrangler deploy`（初期値）のままで構いません。
   - 「デプロイ」を押すと、データベース（D1）も自動で作られます（`wrangler.jsonc` に ID を書かない設定のため）。
3. **設定用トークン（SETUP_TOKEN）を登録する**
   作成された Worker の「設定（Settings）」→「変数とシークレット（Variables and Secrets）」→「追加」で、
   種類 **シークレット（Secret）**、名前 `SETUP_TOKEN`、値に **20 文字以上の推測されにくい文字列** を入れて保存します。
   iPhone の「パスワード」アプリの「強力なパスワード」を使うと簡単です。この値は最初の管理者を作るときだけ使います。
4. **アプリを開く**
   Worker の画面に表示される `https://samurai-dealer-research.<あなたのサブドメイン>.workers.dev` を Safari で開きます。
5. **最初の管理者を作る**
   SETUP_TOKEN と管理者の名前を入れると、**ログイン用キー**（`XXXX-XXXX-…`）が一度だけ表示されます。
   「キーをコピー」して「パスワード」アプリなどに保存してください。続けて「初期データを読み込む」を押すと 30 社が入ります。
6. **ホーム画面に追加**
   Safari の共有ボタン →「ホーム画面に追加」。以後はアプリのように全画面で開けます。

> Deploy to Cloudflare ボタン（`https://deploy.workers.cloudflare.com/?url=<リポジトリURL>/tree/<ブランチ>/mobile`）でも導入できます。
> この場合はリポジトリがあなたの GitHub に複製され、SETUP_TOKEN の入力欄が表示されます（`.dev.vars.example` に記載）。リポジトリが非公開のときは手順 2 の方法を使ってください。

### 更新するとき

GitHub の該当ブランチに新しい版が入ると、Cloudflare が自動で作り直して公開します（Workers Builds）。データ（D1）は残ります。
データベースの形が変わる版では、アプリを開くと「データベースの更新」画面になります。**バックアップを保存してから**「データベースを更新」を押してください（自動では更新しません）。

## 2. 使い方

| タブ | できること |
|---|---|
| 一覧 | 検索、絞り込み（メールあり・フォームあり・要確認・未調査・取得失敗）、分類での絞り込み、件数の集計、CSV 保存（共有シートから「ファイルに保存」など） |
| 詳細（一覧から開く） | 公開メール・問い合わせフォーム・電話のコピー、出典ページ、根拠の抜粋、調べたページ、変更履歴、人による確定値の編集、連絡方法の手動追加、状態の判断、重複・支店の整理、再調査 |
| 候補 | OpenStreetMap（無料）で地域ごとに販売店候補を探す、Google/Bing 等の検索リンク、候補を見てから登録・除外 |
| 追加 | 公式サイトの URL を貼り付けて登録（1 行 1 件）、CSV から登録 |
| 進捗 | 調査の進み具合、停止・再開・失敗分の再実行 |
| 設定 | バックアップ・復元、調査の上限、Firecrawl のキー、利用者の追加・キー再発行・無効化、初期データの再読み込み、ログアウト |

### 調査の進み方

- **アプリを開いている間**：画面が調査を後押しするので、1 社あたり 1〜2 分程度で進みます。
- **閉じている間**：1 分ごとの定期実行で少しずつ（1 分に数ページ）進みます。1 社は最大 10 ページです。
- 各サイトには 2 秒以上の間隔を空け、robots.txt を守ります。CAPTCHA やアクセス制限（403 など）は回避せず「取得失敗」として理由を残します。その場合は詳細画面からサイトを開いて手動で確認してください。

### 判断の決まり（PC 版と同じ）

- 分類・概要は決まった規則で作り、推測で補いません。分からないものは「要確認」になります。
- メールは公式サイト上で見つかったものだけを記録し、URL やアドレスを推測で作りません。採用・個人情報・制作会社のアドレスは除外します。
- **公開メールが見つかっても、営業メールを送ってよいという意味ではありません。**
- 重複らしい販売店は「重複確認待ち」にするだけで、自動では統合しません。

## 3. バックアップと復元

- 設定 →「バックアップを作成して保存」で、販売店・連絡方法・根拠・変更履歴・候補・ジョブを 1 つの JSON ファイルにまとめ、共有シートから「ファイル」アプリや iCloud Drive に保存できます。
- ログイン情報・ログイン用キー・API キーは含みません。
- 復元（管理者のみ）：先に現在のデータのバックアップを保存 → ファイルを選んで「復元する」。読み込みは一時表に行い、件数を照合してから一括で入れ替えます。途中で失敗した場合はデータは変わりません。
- 定期的な保存（例：週 1 回）をおすすめします。

---

## 4. 友人と共有する

- 管理者が 設定 →「利用者」で名前を入れて作成すると、その人のログイン用キーが一度だけ表示されます。本人にだけ安全な方法で伝えてください。
- 権限は「管理者」と「一般」。一般は閲覧・調査・編集ができ、設定変更・復元・利用者管理はできません。
- キーを忘れた・漏れたときは「キーを再発行」（以前のキーとログイン状態は無効になります）。使わなくなった人は「無効にする」。
- 既定のパスワードはありません。ログインに 5 回失敗すると 15 分間ロックされます。通信は HTTPS のみです。

さらに強く守りたい場合は Cloudflare Access（Zero Trust）を前段に置けますが、無料プランでも組織の登録時に支払い情報の入力を求められるため、本アプリでは任意としています。

## 5. 無料プランの範囲（2026-10-24 に Cloudflare の公式文書で確認）

| 項目 | 無料プランの上限 | このアプリでの使い方 |
|---|---|---|
| Workers のリクエスト | 1 日 100,000 回 | 定期実行 1,440 回／日 ＋ 画面操作。通常の利用で十分収まります |
| Workers の CPU 時間 | 1 回 10ms（通信の待ち時間は含まない） | 1 回の処理を「1 ページ取得」または「1 社分の分析」に分けています |
| 外部への通信 | 1 回 50 件 | 1 回の処理で数件 |
| 定期実行（Cron） | アカウントあたり 5 個 | 1 個使用 |
| D1 の読み取り | 1 日 5,000,000 行 | 一覧表示は全件を読むため、販売店が数千件になると多くなります |
| D1 の書き込み | 1 日 100,000 行 | 1 社の調査で数十〜百数十行 |
| D1 の容量 | 5GB | 30 社で数 MB 程度 |
| Workers Builds（自動ビルド） | 月 3,000 分 | 1 回 1〜2 分 |

上限を超えるとその日の処理が止まるだけで、自動で課金されることはありません（有料プランに切り替えない限り）。
`workers.dev` のアドレスは個人・趣味の利用向けとして提供されています。業務で本格的に使う場合は独自ドメインの利用を検討してください。

参考：Workers の制限 https://developers.cloudflare.com/workers/platform/limits/ ／ D1 の制限 https://developers.cloudflare.com/d1/platform/limits/ ／ 料金 https://developers.cloudflare.com/workers/platform/pricing/

## 6. 開発者向け

```bash
cd mobile
npm ci
npm run typecheck
npm test                 # workerd（Miniflare）上で本番と同じバンドルを試験（外部通信は架空サイト）
cp .dev.vars.example .dev.vars   # SETUP_TOKEN を 20 文字以上で記入
npm run dev              # http://localhost:8787
LIVE=1 npx vitest run test/live.test.ts   # 実在サイトでの調査確認（手動・ネット接続が必要）
npm run build:seed       # ../sdr/seed/initial_dealers.json から初期データを作り直す
```

構成：`src/index.ts`（API・定期実行）、`engine.ts`（調査の 1 ステップ）、`fetcher.ts`・`netsafe.ts`（安全な取得・内部アドレスの拒否）、`parse.ts`・`extract.ts`・`classify.ts`・`analyse.ts`（読み取り・判定）、`repo.ts`（データ操作）、`schema.ts`・`db.ts`（版管理）、`auth.ts`（ログイン）、`backup.ts`、`seed.ts`、`public/`（画面）。
データの形は PC 版（`../sdr/`）の版 1 と同じで、販売店 ID・連絡方法 ID の形式も共通です。
